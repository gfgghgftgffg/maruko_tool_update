# Maruko Encode

## 打开界面

在项目根目录：Windows 双击 `start_gui.cmd`；macOS 双击 `start_gui.command`；Linux 运行 `sh start_gui.sh`。所有平台都可直接运行 `python gui.py`。

1. 第一行拖入一个或多个视频，或点击“选择”。
2. 第二行拖入批量文件夹，可选包含子文件夹。两行输入会合并、去重；不用的输入可点“清空”。
3. 第三行选择输出目录；留空时输出到各个源视频旁的 `encoded` 子目录。
4. 勾选 x265、AV1，或同时勾选两者。两者同时勾选会为每个视频分别生成两份文件。
5. 在对应参数框修改参数，点击“开始压制”。参数、勾选状态和路径自动保存到同目录 `config.json`，也可手动点“保存参数”。

进度上方显示 `4/n 个视频 · 当前编码器 · 文件名`；进度条只表示当前这一次编码的进度。更换视频或编码器时重置。音轨提取、封装、检查阶段也会提示，完成检查后才显示 100%。x265 的进度来自解码管道，编码器缓冲会造成少量超前，因此编码结束前最多显示 99%。

“取消”会停止子进程，保留本次临时目录和日志，不发布半成品。窗口关闭时若仍在压制，会先确认取消。

## 参数

- 只支持 x265 和 SVT-AV1。
- 默认 **x265 10bit / AV1 10bit**，位深由 `bit_depth` 控制，界面显示当前实际位深。AV1 CRF 为 **28**、preset 为 **5**，程序不自动调整 CRF。
- CRF 控制质量而不是目标文件大小。原片已经是低码率时，再编码可能增大；完成后会提示哪些输出比原片大，但不会擅自调参数或删除文件。
- x265 参数框填写独立 x265 程序的参数；AV1 参数框填写 FFmpeg 的 libsvtav1 参数。带空格的值用引号包起来。
- AV1 强制使用 `irefresh-type=2`（闭合 GOP），以便生成可靠的随机访问索引。保留填写的 `keyint`；为保证快进，要求它是正整数且不超过 4 秒对应的帧数，超出会报错而不是擅自改值。未填写时默认约 4 秒。当前 `keyint=60` 保持不变。
- 输入、输出、帧率、位深由程序管理，不要在参数框里设置。位深、音频和容器可在 `config.json` 的 `bit_depth`、`audio`、`container` 中修改。
- 当前默认为 10bit、复制第一条音轨、MP4。不保留字幕、附件、章节、多音轨；PQ/HLG HDR 输入会拒绝处理。可变帧率素材可能需要命令行明确指定 `--fps`。

已有输出默认跳过，永不覆盖源视频。**重新压制旧文件时，请选一个新的输出目录**，例如单独的 `encoded_fixed` 文件夹，否则同名结果会被跳过。旧的缺少随机访问点的 AV1 文件不能靠把 MP4 索引前移可靠修复，需要使用闭合 GOP 重新编码。

每次任务的命令、工具输出、耗时、体积对比与结果记录在输出目录 `logs` 下。失败时也保留中间文件。多个输入会产生同名输出时会拒绝开始，以免互相覆盖。

## 跨平台运行

Python 3.11+，Tk 桌面环境：

```sh
python -m pip install -r requirements.txt
python gui.py
```

Linux 可能需要系统安装 `python3-tk`。macOS 使用带 Tk 的 Python。未安装拖放依赖时仍可用选择按钮操作。

依赖安装和路径配置见 [外部工具配置](TOOLS.md)。点击界面的“工具设置”可选择 FFmpeg、ffprobe、x265 10bit 与 MP4Box，并检查解析到的实际路径。

所有启动器支持 `MARUKO_PYTHON`、激活环境和项目 `.venv`。macOS/Linux 还可运行 `sh encode.sh`，带视频路径时命令行压制，不带参数打开界面。

本地 `config.json` 不入库。未创建时读取仓库的 `config.example.json`，界面保存后生成个人配置。实验目录、个人任务记录、视频素材和旧配置备份不存放在项目中。

## 命令行

```powershell
# 默认配置，单个视频
.\encode.cmd "D:\视频\片源.mp4"

# 批量 x265，指定新目录
.\encode.cmd "D:\视频" --encoder x265 --output-dir "D:\压制结果"

# AV1，包含子目录
.\encode.cmd "D:\视频" --encoder svt-av1 --recursive

# 预览命令，不编码
.\encode.cmd "D:\视频\片源.mp4" --dry-run
```

其他选项见 `python encode.py --help`。命令行已有输出默认跳过，仅显式使用 `--overwrite` 才覆盖。GUI 不提供覆盖开关。

## 测试

```sh
python -m unittest test_encode test_gui test_tools -v
```

编码测试使用短测试视频，验证 8/10bit、帧数与帧率、音轨复制、完整解码、批量、异常退出、关键帧间隔、中段快进解码与进度回调。GUI 测试需桌面会话，验证拖放数据、保存与重启恢复、CRF 不变及取消。测试产物在 `build` 下。
